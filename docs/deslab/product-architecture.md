# deslab Obmer: архитектура продукта (черновик, 07.11.2026)

Цель: аддон для Archicad, который продаётся и сразу строит обмерный план и инженерные узлы как надо, без нашего шаблона и без ручных обходов.

## Что сейчас держится на костылях

1. Наш файл шаблона: имена слоёв, видов, листов, избранного, перьев, поверхностей зашиты в код и профиль, 42 листа в шаблоне.
2. Отдельный Python в venv, пути вида `Desktop\Архикад`, ключ ИИ в переменной среды.
3. Подогнанные поправки: смещение чертежа на листе (`offset`), масштаб вида, рамка листа (`frame`), порог 1 м для «в виде только план».
4. Обходы API: чужие элементы не удаляются, заголовок чертежа убирается вторым вызовом, угловое окно не видно штатному API, первая сборка после шага листов иногда падала.
5. ИИ на нашем ключе Polza: расход не считается, клиент зависит от нашей переменной.

## Принципы

- Профиль офиса это данные (JSON), а не код: слои, перья, штриховки, композиты, профили, графзамены, виды, листы, правила черчения.
- Аддон сам «обеспечивает» всё нужное в любом проекте клиента (создаёт недостающее, ничего не трогает чужого) и пишет, что нашёл и создал.
- Всё, что можно измерить в проекте, читается из проекта (поля листа, масштаб вида, этаж, единицы), а не подгоняется.
- Один план на проект: перед построением проверка зоны, чужое не удаляется, предупреждение до платного вызова.
- Результат каждой сборки проходит автопроверку (наложения, размеры против сцены) и пишет отчёт.

## Состав

1. Аддон (C++, Tapir-форк): команды, палитра «deslab Obmer», «Обеспечить профиль», «Новый обмер», лицензия.
2. Ядро (сейчас Python, `bridge`): разбор сцены, ИИ-проверка, построение, листы. Идёт в установщике со встроенной средой выполнения (без venv и без путей пользователя). Вариант на потом: переписать ядро в C++.
3. Профиль офиса (JSON в аддоне): правила и атрибуты, версионируется.
4. Сервер (наш): лицензии, ключ ИИ, учёт расхода, выбор модели. Клиент ключ ИИ не вводит.
5. Набор эталонных квартир (кв. 94 с PDF, Нагорная, JK) с автопроверкой при каждом изменении кода.

## Что надо добавить в аддон (команд создания сейчас нет)

Комбинации слоёв, типы линий, поверхности, строительные материалы, категории зон, системы MEP, мастер-макет со штампом, стили размеров и текстов (читать тоже нечем). До их появления допускается маленький `.tpl` только с атрибутами (без 42 листов), чтобы не требовать наш файл на 150-200 МБ.

## Этапы

1. Профиль как данные: вынести всё зашитое (имена, поправки, пороги) в `office-profile.json`, убрать подгонки или заменить измерением. Тесты на эталонах.
2. «Обеспечить профиль»: команды создания недостающих атрибутов, видов и листов в чистом проекте. Новые команды аддона для шести групп выше.
3. Упаковка: установщик, встроенная среда выполнения, настройки в палитре, журнал.
4. Сервер: лицензия, ИИ через наш сервер, учёт расхода (стоимость вызова на кв. 94 сейчас 15-21 ₽).
5. Другие версии Archicad (28, 29) после стабилизации 27.

## Открытые вопросы к Игорю

- Клиенты: бюро с нашими стандартами или любые, со своими шаблонами (от этого зависит, нужен ли «профиль клиента»).
- Версии Archicad: только 27 или сразу 28/29.
- Продажа: лицензия, подписка, оплата ИИ по расходу.
- Нужна ли работа без интернета (тогда ИИ локальный или отключаемый).
- Языки интерфейса и единицы (метры, миллиметры).
