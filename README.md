# deslab Archicad add-on

Fork of [Tapir](https://github.com/ENZYME-APD/tapir-archicad-automation) (MIT license, see `LICENSE`)
with commands that deslab needs for drafting in Archicad 27 from Claude.

- Upstream snapshot: ENZYME-APD/tapir-archicad-automation @ `a88df4ce5c3d62b9038fba782b60308681d98a6a` (Tapir 1.7.4).
- It is a drop-in replacement for Tapir: same JSON command namespace, so the `archicad-mcp` server keeps working.
  Disable the original Tapir add-on in Archicad before loading this one, and do not accept Tapir's
  "update to the latest version" prompt, which would replace this build with upstream Tapir.
- The build runs in GitHub Actions (`.github/workflows/build_ac27_win.yml`) on every push.
  Each main build is attached to the `ac27-latest` release, builds of other branches to the `ac27-dev` pre-release;
  no Visual Studio is needed on the drafting PC.

## deslab changes

| Command | Change |
| --- | --- |
| `CreateWindows` | Optional `cornerWindow: true` places the window with the Corner Window tool variation (`APIVarId_CornerWindow`) and that tool's defaults. `favoriteName` / `libraryPartName` are applied to the Corner Window tool defaults too, with `ac_cw_function` on, so a corner pair can be placed as e.g. «Двустворчатое Окно 27». |
| `CreateWindows`, `CreateDoors` with `libraryPartName` | The tool defaults take the parameter block Archicad prepares for a new element of that part (`ACAPI_LibraryPart_OpenParameters`/`GetActParameters`) instead of the raw `ACAPI_LibraryPart_GetParams` list; with the raw list the GDL parameters of an «Окно 27» window could not be read or set afterwards. |
| Create and modify commands (`CreateElementsCommandBase` and the shared helpers in `ExtendedElementCommands.cpp`) | When Archicad refuses the undoable change (a modal dialog is open or another command runs), the command answers with an error instead of an empty element list. |
| `BuildModelFromScan` | New. Builds walls, doors, windows, floor slabs and zones from a point cloud: runs the `deslab-scan2bim` helper (`scan2bim/`, shipped as `deslab-scan2bim-win.zip` in the release, unzipped next to the add-on) on an E57, or takes its scene JSON, then creates the elements with the CreateWalls/CreateDoors/CreateWindows/CreateSlabs/CreateZones logic. Optional favorites, building materials (by name) and layers (by name). Defaults: walls and slab in reinforced concrete (not the brick of the default settings), windows with one sash up to 0.9 m, two up to 1.9 m, three above (three even panes, `gs_iPanesConfig` 1), opening into the room, set back from the facade (`windowSetback`), with handles and an outer sill, no inner board, frames and sashes in white plastic (`windowSurface`), a balcony door built as a window, one slab to the outer outline of the walls (scene `slabs`). Walls, openings, slabs and zones are created directly on their layers (the tool default layer is switched for the call and restored), so a hidden default layer cannot refuse them. Wall ends that meet (within 5 mm) are made to meet exactly, an L corner in one point and a T joint on the other wall's line, so Archicad joins them into one outline with one hatch. Walls are always square to the axes (a scanned wall that leans a little is placed at its average position, never drawn at an angle). The helper gives walls on one line, end to end, one common back face (no jog at the entrance door, no false step on the outer face). A scene window may carry `cornerWindow: true` (Archicad's own corner window pair instead of two windows with a column between; the bridge builds such pairs itself after the model, see bridge/README.md) and `gdlParameters` (name/value list set on the created window last, e.g. even sash widths). The helper leaves low clutter out of the walls (a wall face must be seen above 1.5 m) and lists the first row of blocks of new walls as scene `tracing`, which the bridge builds as low walls with dimensions, as it builds the scene's `mep` items (shafts, risers, radiators). See `scan2bim/README.md`. |
| Analytical Model commands | Left out of the build (`DESLAB_NO_ANALYTICAL`): linking AnalyticalModelAPI.dll is suspected of making Archicad 27.0.0 R1 (5003) refuse the add-on. |

| `CreateAssociativeDimensions` | Changed. A witness point takes an optional `textPosition`: the text of the segment ending at that point is fixed at that offset from the segment middle on the dimension line, as if moved by hand (for short segments whose text Archicad pushes onto the wall; reliable on the last segment of a dimension). Or `textLeader` (beg, mid, end): the text goes on a leader line, as the office template does (set in a second undo step after the dimensions are created, when their witness points have settled, in absolute coordinates; a dimension whose leaders cannot be set, e.g. on a hidden layer, is reported as an error, underlined, text at 0° or 90°, leader in the text pen; the segment is found by position along the chain, because Archicad may reorder the witness points; a chain with leaders pointing left or down is sent reversed, since Archicad turned its texts by 180°; `textLeader` takes optional `pen` and `anchorAtTextEnd`, default true as in the template). 11.11.2026: `textLeader` also takes `dot` (`pen`, `size` in mm): the leader starts with a filled dot like the opening labels (the bridge sends pen 167, 0.5 mm, profile `leaderDotPen`/`leaderDotSize`); without it the leader has no arrowhead. The bridge sends leader pen 120 (profile `leaderPen`). A witness point may also take `textAt` (absolute): the text of the segment ending there slides along its line to that middle, set in the same second step, so no crossing line runs through it. Optional `textFontName` (08.11.2026): the texts' font, since a favorite does not set it and a new project's tool defaults are Archicad's own; the bridge sends the template's GOST font, 2.5 mm, pen 120 (profile `dimensionText`). `GetDimensionData` also returns each witness point's `note` (fixed position, angle, leader line). A text leader has no arrowhead (11.11.2026: a new project's dimension defaults drew a blue one). |

| `ApplyOfficeStandard` (new) | Игорь 07.11.2026: the add-on sets up the office standard in any open project itself (no template copy). Step 1, attributes: reads pen sets, line types, fills, surfaces, building materials, composites, layers, layer combinations and zone categories from the standard file with `ACAPI_Attribute_GetAttributesFromProject` (the file is not opened) and creates the missing ones with `ACAPI_Attribute_CreateExt`, moving their references (fills, surfaces, building materials, line types, layers) to the new indices; an attribute with the same name is kept; a source guid already held by another name is replaced by a fresh one. Optional `updateExisting`: same-named attributes take the standard's settings too; the palette sets it for an untitled project (08.11.2026: Archicad's own «Бетон - Конструкционный» kept its green cut fill pen in a new file). | `CaptureOfficeStandard` (new) | Writes the open project's layers, surfaces, building materials and layer combinations with their layer statuses (source indices and guids kept) to the standard package that `ApplyOfficeStandard` reads. The first step of «Снять стандарт с шаблона». Also the graphic override rules and combinations; `ApplyOfficeStandard` creates the missing ones (by name) after the attributes, with the attribute guids in their criteria and styles replaced where they changed, and the layer indices of Layer-property criteria moved to the open project's layers. Also the story views of the View Map with their folders and settings (layer combination, scale, pen set, override combination, structure display, renovation filter, model view options and dimension standard; the last two by name, or as custom view settings where the open project has no such named set). The library part of the model view options is written per view by parameter name by `CaptureOfficeStandard`; `ApplyOfficeStandard` does not apply it yet. Archicad 27 does not take a view's own model view options from `ACAPI_Navigator_ChangeNavigatorView` (the view kept the stock combination current at the time, with «hide zone stamp» on), so the window's options are set to the standard's while such views are made and put back after (once per run of views with the same options; the library part stays the window's own). The view-option blocks Archicad hands out are not deleted (that corrupted the heap). The steps are traced to `%TEMP%\deslab-apply-trace.log`. `ApplyOfficeStandard` creates the missing views by folder path and name. The favorites are exported next to the package (`<name>-favorites.prf`) and imported with their folders, keeping favorites of the same name. Master layouts (size, margins and their lines and texts, e.g. the title block, autotexts kept as keys; drawn only into an empty master), the pen sets in effect for the model and for layouts (by name), and the project info fields the open project has left empty and the Layout Book's layouts (name, numbering, master) are created where missing (11.11.2026: with the lines and texts drawn on them, e.g. the legend table, the note and the approval block, a text block keeping its set width so its lines wrap as in the standard; a layout numbered by the standard's subsets keeps the number it shows there, «04», as its own number; a new project called it «AP1»); a master of the same name takes the standard's size and margins. A rule whose fill background is transparent (pen 0, which Archicad refuses on creation) is made without it and the background set afterwards; the report names a rule that stays without it. 12.11.2026: a layout's content also carries its objects (the north sign): library part name, place, angle, size, pen and the simple parameters, placed again by `ApplyOfficeStandard`; a layout text whose run is in a font the project does not have is drawn in the text's own font instead of being lost (internal `fontFallback` flag of the text style/run, the `CreateTexts` behaviour itself is unchanged). |
